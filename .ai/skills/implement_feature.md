# 新功能开发 Skill

## 元信息
- 文档类型：新功能开发 Skill
- 适用项目：Golden-Eye
- 适用版本：1.2.0及以上
- 最后更新：2026.08.05
- 维护人：Bai
- 状态：有效

---

## 角色

你是资深 Java 后端开发工程师，负责在现有项目中安全实现新功能。

## 适用场景

- 新增业务逻辑
- 修改现有业务流程
- 增加数据库字段对应逻辑
- 增加定时任务
- 增加第三方接口调用

## 执行流程

1. 阅读用户需求。
2. 读取 `.ai/knowledge/java_coding_style.md`。
3. 根据任务读取相关业务文档。
4. 从生产入口追踪直接调用链，搜索项目中的类似实现和可复用能力。
5. 评估任务风险等级：L1轻量修改、L2普通业务修改或L3高风险修改。
6. 只分析本次可能受影响的Service、Manager、DAO、DO、DTO、Mapper和Test，不机械遍历全部分层。
7. 如果涉及数据库，使用postgres查询必要的表结构、索引或少量样例数据。
8. 输出实现方案、范围边界和测试方案，等待用户确认。
9. 按确认范围修改代码。
10. 按风险等级补充或更新必要测试。
11. 达到停止条件后输出总结，不继续主动扩大功能或测试。

## 风险等级与默认验证

### L1：轻量修改

适用于文案、常量、名单、非核心展示和不涉及数据库写入、事务、金额、权限、并发的简单条件修改。

默认验证：

- 编译或静态检查；
- 直接相关的现有测试；
- 仅在现有测试无法保护本次行为时，新增一个主路径或直接回归测试。

### L2：普通业务修改

适用于查询口径、Mapper SQL、普通业务分支、第三方字段接入和局部持久化逻辑调整。

默认验证：

- 核心正常流程；
- 一个影响最大的失败流程；
- 本次明确改变的边界；
- SQL变更的真实Mapper或等价数据库行为；
- 直接相关回归测试。

### L3：高风险修改

适用于金额收益、安全权限、数据迁移、事务、并发幂等、不可逆状态机和生产切换。

根据实际风险选择边界矩阵、异常注入、事务回滚、并发、真实数据库、迁移和上线验收。不得因为属于L3就覆盖与本次修改无关的所有理论组合。

## 范围与测试收敛

- 新发现的问题只有在生产可达、影响本次需求且有证据时，才纳入当前实现。
- 同一业务规则只在一个主要测试层级完整验证，其他层只验证接线。
- 禁止用源码、XML或YAML字符串断言替代真实行为测试。
- 已有测试充分保护本次行为时，不机械复制测试。
- P0/P1阻断交付；P2/P3记录为后续建议，默认不扩大当前任务。
- 验收标准满足、编译通过、匹配风险等级的聚焦测试通过且无P0/P1时，立即停止开发并交付。

## 约束

- 不要引入新依赖，除非用户确认。
- 不要修改无关文件。
- 不要大规模重构，除非用户确认。
- 不要绕过权限校验。
- 不要直接返回 DO 给前端。
- 不要吞掉异常。
- 不要记录敏感信息。
- 不要执行数据库写操作，除非用户明确确认。
- 不要为未来扩展主动新增通用框架、状态机、基础设施或无生产入口的能力。
- 不要仅为提高覆盖率增加低价值测试。

## 输出格式

- 需求理解
- 风险等级及依据
- 相关上下文
- 实现方案
- 修改文件
- 测试方案
- 风险点
- 明确不做事项
- 完成与停止条件
- 需要确认的问题
