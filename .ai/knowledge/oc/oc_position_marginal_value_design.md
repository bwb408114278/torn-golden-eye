1. **替补标尺不按历史填充中位数，不按 `slot_short_code` 合并。** 每个具体 `slot_code` 独立取值。

5. 跨 OC 仍按业务基线 R6 的**链级单位人天产出 × 开动紧迫度**。

## 2. 不可动业务边界

1. 推荐目标是让帮派赚更多钱，不是分钱公平；个人分钱与帮派排序分开。
2. 核心岗正常情况下应由 70 以上的人填；65/60/55 门槛包含救急防停转含义，不代表理想水位。
3. 不满核心水位的人去大众岗，或低一级 OC 核心岗带新人；不同等级错峰，不挤同一层。
4. 9 级链式失败代价高，但不得跨等级统一绝对分数线；当前标尺规则是 9 级直接取各自门槛。
5. 链式前置 `Stacking the Deck / Lock Stock / Manifest Cruelty / Gone Fission` 无自有收益，成功收益在后置 OC；不做大成功分级。
6. 结局奖励写 `torn_setting_oc_flow_node.reward_value`，不建独立结局表，不写 `label`。
7. 严格准入不变：同一（OC、等级、岗位短码）必须有实测记录且达到岗位门槛；无记录不可填。
8. 同一 OC 的多个空位逐条参与并完整输出；负 ΔV 候选也保留，只后置，不过滤。
9. 不改 `OcBannedNoticeService`、`OC新队` 规划器和分钱系数表。

## 3. 当前计算口径

### 3.1 逐坑替补标尺

```text
rank 7/8 且 requirement >= 65（核心）：substitute = min(85, requirement + 5)
rank 7/8 且 requirement <= 60（大众）：substitute = min(85, requirement + 10)
rank 9：                              substitute = min(85, requirement)
```

- 粒度固定为 `(OC, rank, slot_code)`。
- 不读取历史填充中位数，不按 `slot_short_code` 合并，不叠加 priority、人口分位或额外能力档。
- 当前 42 个候选岗位的最高标尺为 70，85 上限只是保留原规则的防御边界。

### 3.2 DAG 基线与个人边际

对每个候选分别构造基准队伍；只改变当前坑位，其他坑位保持标尺：

```text
base[s]       = substitute(s) / 100
S0 / V0       = DAG(base)
S1 / V1       = DAG(base，但当前候选坑位换成成员实测 pass_rate / 100)
ΔV(m, s)      = V1 - V0
```

普通 OC 使用分结局期望奖励：

```text
V = Σ（每个 GOOD_END 的到达概率 × 该结局 reward_value）
```

BAD_END 奖励为 0。不能再用 `ΔS × OC平均奖励` 冒充分结局结果。

**一个完整实例（3359579 → BTB `Thief#2`）：** 其他岗位保持标尺，当前坑由 70 换成他的 71。DAG 总成功率从 77.3778% 升到 77.8707%（+0.4929 点）；逐结局奖励加权后的队伍期望收益从 259.2006M 升到 260.8004M，所以 `ΔV = +1.5998M/期`。这计算的是“他加入”相对“70 分标尺替补加入”的期望差，不是个人分成，也不是必定多赚。

### 3.3 链式前置

以 Stacking the Deck → Ace in the Hole 为例：

```text
chainValue(Ace) = V0(Ace)
V(StD)          = S(StD) × chainValue(Ace)
ΔV(StD, s)      = [S1(StD) - S0(StD)] × chainValue(Ace)
```

本次固定标尺下：

| 链 | 计算 | 链级期望价值 | 链人天 | 单位人天 |
|---|---|---:|---:|---:|
| StD → Ace | 75.95% × 307.306M | 233.385M | (4+5)×6=54 | 4.322M |
| Lock Stock → Hostile | 74.68% × 450.401M | 336.370M | (5+6)×6=66 | 5.097M |

前置岗位不展示个人收益；链级单位人天只用于跨 OC 排序。

### 3.4 核心胜任等级锚点

仅用 ΔV 的正负确定推荐等级，不用 ΔV 金额跨 OC 比大小：

```text
Rcore     = 存在至少一个“核心岗且 ΔV >= 0”候选的最高 rank
Rpositive = 存在至少一个“任意岗位且 ΔV >= 0”候选的最高 rank
锚点 R    = Rcore；若不存在则 Rpositive；若仍不存在则最高可填 rank
```

候选分三组，全部保留：

| 组 | 条件 | 含义 |
|---|---|---|
| 主推荐 | `rank <= R && ΔV >= 0` | 锚定等级及以下、不会比标尺替补差 |
| 后置 | `rank <= R && ΔV < 0` | 救急候选，仍输出 |
| 高等级后置 | `rank > R` | 即使大众岗 ΔV 为正，也不能仅凭大众岗把成员推到尚未胜任核心岗的等级 |

### 3.5 每组内部排序

```text
1. rank 降序
2. 核心岗（门槛 >=65）优先于大众岗（门槛 <=60）
3. 链级单位人天产出 × 开动紧迫度 降序       // 跨 OC，业务基线 R6
4. 既有经济决胜键与 ocId 确定不同队伍
5. ΔV 降序                                  // 仅同一 OC 内选坑，不跨 OC 比金额
6. slotId 升序

先确定不同队伍再比较同队ΔV，是为了让比较器满足传递性；不能写成“不同OC简单跳过ΔV”的条件比较器。
```

本次“所有队都没有人”的模拟中，所有队都是新队，紧迫度均为 0.95，所以第 3 键退化为链级单位人天产出。真实快照回放另覆盖停转命中。

### 3.6 百分制展示

R6 经济分继续使用 0.5M/12M 的对数锚点，但不能再单独作为全序展示分。最终展示分按「分组 → rank → 核心/大众 → R6经济分」的固定带宽合成，与完整顺序单调不减；整数四舍五入允许同分。

ΔV 只在同 OC 内决胜，不需要新增 ΔV 金额展示锚点。展示分不反向参与比较，避免为了显示而改动已确认的业务顺序。

## 8. 已撤销的错误口径

| 撤销项 | 原因 |
|---|---|
| 按 `slot_short_code` 合并历史填充标尺 | 同短码不同坑位在 DAG 中重要性不同；合并会抹掉 CHECK、路径和敏感度差异 |
| 用 `Thief#2 = 73` 等历史填充中位当当前标尺 | 历史填充分工不是本轮反事实替补定义；用户已重新明确固定门槛偏移规则 |
| 只下调 BTB、却继续让 CP 使用 74 等历史标尺 | 标尺必须同口径覆盖全部 7/8/9 级目标岗位，不能逐队挑参数 |
| 纯 ΔV 跨 OC 直接排序 | 已实证倒向低门槛/大众岗；ΔV 金额只用于同 OC 内选坑 |
| `V0 × (1 + ΔV/V0)` | 展开为 `V0 + ΔV`，队值重复计算 |
| 负 ΔV 直接整级沉底，或核心岗无条件压过非负大众岗 | 前者会埋掉合理的 8 级核心，后者会让 pakeh 的 −1.519M 核心岗压在非负大众岗前 |
| 用平均奖励乘 ΔS 代替分结局收益 | 当前奖励已经落在 GOOD_END，应直接计算结局概率加权价值 |
| CP/StD 图存在显著结构错误 | 临时脚本未归一化参与者编码；修正脚本后误差为 +0.24/+0.82，不成立 |

### 9.1 配置与数据

另补 `add_lock_hostile_chain_if_missing`：仓内原初始化漏掉 `Lock Stock → Hostile Takeover`。迁移使用标量子查询取下一 ID，外层 `NOT EXISTS` 防重；真实库已有链时只读 SELECT 验证返回 0 行，缺失时才返回一行，避免 PostgreSQL 聚合空集仍返回一行导致重复插入。

## 10. 保留边界

1. Ship Happens、Crane Reaction 的结局奖励未灌；Manifest Cruelty → Gone Fission → Crane 因终端缺奖励整链回退 R6，不伪造 ΔV。
2. r10 的固定 DAG 标尺未定义，当前回退，不套用 r9。
3. 成员能力会涨。真实用户完整顺序属于当前快照，集成验证只在显式开关下运行，不硬编码为普通 CI 的永久顺序断言。
4. 通用岗位表与帮派门槛覆盖是两种场景；生产保留覆盖，模拟对比时必须明确使用哪一种。

## 11. 停止条件

- 为迎合某个用户而单独调整某支 OC 的标尺；标尺必须全目标岗位同规则。
- 再按短码合并坑位，或把 priority 额外叠入核心/大众分层。
- 用 ΔV 金额直接跨 OC 排序，或重复计算队值。
- 为得到预期顺序而删除负 ΔV、无记录或门槛不足候选的真实信息。
- 缺图/缺奖励/缺链值按合法 ΔV=0 处理；缺失必须是 null 并回退。
- 数据/图校验未通过时，不靠调参掩盖。
