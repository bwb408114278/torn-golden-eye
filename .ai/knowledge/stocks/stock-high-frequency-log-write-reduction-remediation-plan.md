### 1.2 当前真正阻断全量测试的证据

失败集中于：

```text
src/test/java/pn/torn/goldeneye/repository/mapper/torn/stocks/TornStocksHistoryMapperTest.java
```

其中仅以下两个测试使用 `insertRealtimeIgnoreConflict(...)` / `insertBackfillReturningSlots(...)` 触发**数据库默认 identity 分配**：

```text
insertRealtimeIgnoreConflict_identityIdGeneratedAndReplaySkipped()
insertBackfillReturningSlots_returnsInsertedSlotsOnlyAndEmptyOnReplay()
```

本地共享同步 PostgreSQL 的只读实测：

| 指标 | 当前值 |
|---|---:|
| `MAX(torn_stocks_history.id)` | `2089946231974512216` |
| identity sequence | `public.torn_stocks_history_id_seq` |
| sequence `last_value` | `2089946231974400054` |
| `is_called` | `true` |
| 下一个 identity 候选值 | `2089946231974400055` |
| `id >= 下一个候选值` 的已有行数 | `112197` |

结论：共享库中存在显式高 ID 同步/导入后 sequence 水位落后的事实。两个测试的自定义 INSERT 均不携带 `id`，因此在验证自然分钟幂等语义**之前**就被主键冲突拦截：

```text
共享同步写入显式雪花 ID
→ identity sequence 未随外部同步持续推进
→ 测试自定义 INSERT 请求下一 identity 值
→ 主键唯一约束冲突
→ 测试不能证明 ON CONFLICT / RETURNING 的目标业务语义
```

这不是日志降写代码引入的错误，也不能被解释为 `ON CONFLICT (stocks_id, date_trunc(...))` 的失败：主键 `id` 冲突不属于该冲突目标。

## 2. 生产与数据库契约

### 2.1 `torn_stocks_history` 的真实写入边界

```text
TornStocksManager.spiderStockData()
→ TornStocksHistoryDAO.insertRealtimeIgnoreConflict(...)
→ TornStocksHistoryMapper.xml
→ INSERT ...（不携带 id）
→ PostgreSQL GENERATED BY DEFAULT AS IDENTITY
→ ON CONFLICT (stocks_id, date_trunc('minute', reg_date_time)) WHERE deleted=0 DO NOTHING
```

Tornsy 回填走独立入口：

```text
TornsyStockHistoryBackfillService.backfillStockSlice(...)
→ TornStocksHistoryDAO.insertBackfillReturningSlots(...)
→ INSERT ...（不携带 id）
→ identity
→ ON CONFLICT ... DO NOTHING
→ RETURNING 实际插入的 (stocks_id, minuteTime)
→ 仅实际插入槽驱动 Bar / Feature 数据修复
```

`stocks-history-identity.yaml` 的已执行 changeSet 将主键改为 `GENERATED BY DEFAULT AS IDENTITY`，用于修复此前自定义 INSERT 因 `id` 未赋值导致的生产分钟断流。这个生产契约仍然有效，**不得因删除测试而回退 identity、改为 Java 手工 ID、修改 Mapper 或改写已执行 changeSet**。

### 2.2 共享同步测试库的确定性边界

当前本地库持续接收带显式雪花 ID 的同步数据。即使 Mapper 测试使用：

```java
@Transactional
@Rollback
```

也不能使 identity 测试稳定：

1. `nextval()` 的 sequence 前进不受事务回滚保护；
2. 外部同步不属于测试事务，可能任意时刻插入比 sequence 更高的 ID；
3. 测试前 `setval()` 会修改共享库并掩盖真实同步问题；
4. 物理删除 2099 测试行也不会修复 sequence 水位；
5. 手工设置实体 `id` 会绕过生产 Mapper 的 database-default identity 行为，不能证明本来要验证的契约。

因此，依赖“共享数据库的 identity sequence 当前高于所有显式同步 ID”的测试不可作为持续 Maven 发布门禁。

> 本文只对**本地共享同步库**作出以上结论。不得据此推断生产数据库一定存在 sequence 漂移，也不得对生产执行 `setval`。生产部署/排障若出现同类主键错误，应先在目标库按只读流程读取 `MAX(id)`、`last_value` 和 `is_called` 后再决定是否需要独立的追加式运维修复。

## 3. 测试保留/删除决策

### 3.1 必须保留：每日缺口巡检的真实 Mapper 查询测试

保留 `TornStocksHistoryMapperTest` 的以下四个测试，不改为 Mock，不合并为源码字符串断言：

| 测试 | 生产调用链 | 必须保留的原因 |
|---|---|---|
| `selectMinuteCounts_fullDayDistinctMinutes_returns1440` | `TornsyStockHistoryBackfillScheduler.inspectYesterdayAndBackfillIfNeeded()` 以 `1440` 判定整天连续性 | 验证数据库实际 `COUNT(DISTINCT date_trunc('minute', ...))` 口径，纯 Mock 无法发现 SQL 聚合错误。|
| `selectMinuteCounts_missingMinutes_returnsBelow1440AndAbsentRowForEmptyStock` | 调度器将缺失 SQL 行按 `0` 解释并触发回填 | 验证“1439 必须缺口”和“没有 SQL 行不是完整”的核心 fail-closed 语义。|
| `selectMinuteCounts_halfOpenRange_excludesEndBoundary` | 巡检窗口为昨天 `[00:00, 次日00:00)` | 防止右边界重复计入今天 00:00 的数据，影响昨天连续性和回填范围。|
| `selectMinuteCounts_deletedDuplicateRow_notCountedAndNotInflated` | 查询 SQL 固定 `deleted = 0`；部分唯一索引允许同一分钟 `deleted=1` 行存在 | 防止逻辑删除/历史异常行被误计为有效分钟，导致缺口漏检。|

这四个测试通过 MyBatis-Plus 标准 `save/saveBatch` 写入应用层雪花 ID，不依赖 PostgreSQL identity sequence；同线程 `@Transactional + @Rollback` 可覆盖其写入，不需要新增 `@AfterEach` 物理清理。

### 3.2 必须删除：依赖共享 identity 水位的两个 Mapper 测试

删除以下两个 `@Test` 方法，连同只服务于它们的断言/Javadoc 描述：

| 删除目标 | 删除原因 |
|---|---|
| `insertRealtimeIgnoreConflict_identityIdGeneratedAndReplaySkipped()` | 同时耦合“identity 默认分配可用”和自然分钟重放。当前共享库会在进入自然分钟唯一约束前发生主键冲突；该测试无法提供稳定业务证据。实时入口的“自然分钟键、全量插入才派发、全冲突不派发、部分冲突 fail-closed”已由 `TornStocksManagerTest` 稳定保护。|
| `insertBackfillReturningSlots_returnsInsertedSlotsOnlyAndEmptyOnReplay()` | 同样先依赖不稳定 identity。回填服务的“只有实际返回 slot 才重建、冲突空 slot 不重建、部分冲突只使用实际 slot”已由 `TornsyStockHistoryBackfillServiceTest` 的编排测试稳定保护。|

删除不是否定生产 identity 修复，而是删除**在持续同步共享库中无法确定性运行**的环境耦合门禁。未来如拥有明确隔离且停止外部同步的数据库，可单独设计 identity/升级迁移验收，不得把同类测试重新塞回当前共享库 Maven 门禁。

### 3.3 测试收敛后的证据矩阵

| 规则 | 保留的主证据 | 不再重复的证据 |
|---|---|---|
| 每日巡检的 minute-count SQL | `TornStocksHistoryMapperTest` 的 4 个真实 PG 查询用例 | 无需在 Scheduler Mock 测试复制 SQL 边界矩阵。|
| 实时分钟自然键与下游控制 | `TornStocksManagerTest` | 不用不稳定 PG identity 首插测试重复证明。|
| 实时 `ON CONFLICT` 实际返回数 | `TornStocksManagerTest` 的全量/全冲突/部分冲突编排分支 | 当前共享库不再强制真实 identity Mapper 门禁。|
| 回填实际 slot 驱动派生修复 | `TornsyStockHistoryBackfillServiceTest` 的空返回、部分冲突、影响桶和 30 日闭包测试 | 当前共享库不再强制 `RETURNING` + identity 首插 Mapper 门禁。|
| PostgreSQL identity 迁移可用性 | 已执行的 `stocks-history-identity.yaml` 与目标环境发生真实故障时的只读诊断/独立运维验收 | 不在持续同步的共享开发库中模拟 sequence 水位。|

### 5.3 非阻断环境说明

即使本类 4 项稳定 Mapper 测试通过，仓库全量 Maven 仍可能遇到与本次无关的：

```text

NoClassDefFoundError

```

下一轮 Review 必须分开报告：


不能把无关全量环境错误误归因于本次测试收敛；也不能把“本类 4 项通过”伪装成全库测试通过。
