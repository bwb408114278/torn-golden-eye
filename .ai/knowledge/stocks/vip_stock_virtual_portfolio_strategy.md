## 2. 当前主策略结论

### 2.1 α是唯一新入场主策略

当前阶段不是把α加入旧版候选集合，也不是让α与旧版策略共同竞争。业务主线已经切换为：

```text
α=0.04
→ 股票提醒第一批唯一新入场策略
```

旧版三类BUY策略、旧版`qualityScore`和旧版五槽竞争不再决定新α目标。它们只保留在历史批次、迁移收尾或明确的紧急回退语境中。

数据和存量状态需要连续，不代表旧版策略继续拥有新业务决策权。

### 2.2 发布顺序

```text
第一批：股票提醒
→ 验收α选股、Top1目标、成交、批次、目标变化SELL和消息

第二批：炒股推荐
→ 消费第一批冻结的α快照和结果
```

第二批不得反向改变第一批公式、股票池、决策周期或Top1结构。

### 2.3 收益原则

项目持续追求更高的风险调整后收益，但：

- 历史年化不是收益上限；
- 历史收益不是未来承诺；
- 已经查看并用于选择α=0.04的数据不能再称为新的盲测样本外证明；
- 新增数据只能在规则冻结后作为前向观察证据；
- 不能为达到阶段收益目标反向调整参数。

## 3. α=0.04长期冻结规则

### 3.1 公式

```text
r20(i,t) = close(i,t) / close(i,t-20个有效观察日) - 1
r1(i,t)  = close(i,t) / close(i,t-1个有效观察日) - 1
R20(i,t) = rank(-r20(i,t))
R1(i,t)  = rank(r1(i,t))
alphaScore(i,t) = 0.96 × R20(i,t) + 0.04 × R1(i,t)
```

`R20`是主因子，表示近期跌幅越大的股票排名越靠前；`R1`是辅助因子，表示最近1日反弹越强的股票排名越靠前。

α=0.04是评分权重，不是资金、仓位、交易次数或股票数量。

### 3.2 股票池

- 使用已经冻结的35支生产股票；
- 当前首批实现的冻结成员为生产 `stocks_id=1..35`，股票池版本为 `STOCKS_35_V1`；
- 当前成员摘要为对升序ID串 `1,2,3,...,35` 计算的固定摘要：
  `0620dc9876a92272bf8358b21731a40ad31b3556aeb41a7e6f798c8a2f4c041a`；
- `TCSE`只作市场参考，不参与选股；
- 股票池不得按结果临时修改；
- 股票池变化必须产生新版本并重新验收；
- 排名只在固定股票池内进行。

当前数据库中的Alpha快照为空不代表股票池未实现；生产部署前尚未执行预填时允许为空。正式新入场前必须在生产环境通过超管机器人指令完成预填和质量校验。

### 3.3 日线输入

α选股使用日线收盘快照：

```text
Asia/Shanghai自然日内最后一根可用15分钟bar.lastPrice
```

15分钟bar是执行和数据质量来源，不代表每15分钟重新选股。缺失日线不得使用插值、前值、后值、当前价格或0补齐。

### 3.4 有效观察和预热

- `r20`需要20个有效观察日间隔；
- `r1`使用前一个有效观察日；
- 横截面排名使用共同有效自然日；
- 首批新入场前至少完成60个共同有效自然日预热；
- 预热或数据不足期间可以构建数据，但不得产生新α BUY；
- 价格必须为有限正数。

### 3.5 排序

```text
alphaScore DESC → stocksId ASC
```

禁止使用无序数据库结果、集合遍历顺序、股票简称、未来收益、成交结果或持仓结果改变排名。

## 4. α主策略组合和生命周期

### 4.1 决策周期

```text
每5个共同有效自然日检查一次
phase = 0
```

非决策日不重新选目标，不因15分钟短期波动改变目标。

### 4.2 Top1和Top3迟滞

- α主策略只持有Top1；
- 当前没有持仓时选择Top1；
- 当前持仓仍在全股票池Top3内时继续持有；
- 当前持仓跌出Top3且新Top1不同，才允许目标变化；
- Top3是迟滞范围，不是持仓数量；
- 不得把Top1扩展成Top3或Top5。

### 4.3 组合容量和资金

当前主组合的α逻辑结构为：

```text
最多1支股票
目标资金使用比例100%
```

资金槽复用现有表`torn_stock_portfolio_slot`，通过组合CODE隔离不同业务账本：

```text
VIP_FORMAL = 旧版正式组合，5个2B槽位
VIP_ALPHA  = α正式组合，1个10B逻辑槽位
```

`VIP_ALPHA`使用独立10B资金进行买卖和结算；不占用、不挪用`VIP_FORMAL`槽位。旧版与α允许同时持有同一股票，但必须保持批次、规则版本、资金、消息和收益统计隔离。

### 4.4 BUY

α排名Top1是新入场的唯一选股依据。新入场不再经过旧版三类BUY、旧版质量分或旧版风格门禁。

只有在数据完整、预热完成、达到决策点、没有α开放持仓并且下一根严格连续可用15分钟bar能够执行时，才可以形成新BUY。

### 4.5 SELL

α主策略的唯一正常SELL是目标变化：

```text
到达α决策点
AND 当前持仓跌出Top3
AND 新Top1与当前持仓不同
→ ALPHA_REBALANCE
```

α首批不使用：

- `+0.8%`固定目标退出；
- `-1.5%`固定风险退出；
- `14天`固定时间退出；
- RANGE专属退出；
- 动态峰值回撤退出；
- 旧版无状态市场SELL；
- 因新股票更高排名而产生的无来源SELL。

数据不足或断层时不伪造SELL。当前α持仓保持，等待下一次合法的α决策点；本轮记录数据不足或执行失败原因。

管理或人工强制关闭如确有需要，属于非策略管理事件，不能标记为`ALPHA_REBALANCE`，也不能混入正常α策略收益统计。

## 5. 执行和批次原则

### 5.1 下一连续bar成交

所有α入场和目标变化退出都必须遵守：

```text
决策时点
→ 下一根严格连续且可用的15分钟bar
```

不得跨数据断层寻找更晚bar，不得使用未来bar参与排名，不得用信号价格冒充成交价。沿用现有股票提醒已经冻结的价格质量、跟随截止和消息幂等规则；本次不为α新增另一套成交机制。

### 5.2 批次

沿用现有系统批次、资金、成交和通知基础设施，不新增第二套α生命周期。批次通过`portfolio_code`区分`VIP_FORMAL`旧版正式组合和`VIP_ALPHA`α正式组合；同一`stocks_id`允许在两个组合同时存在，但任何SELL只能配对同一组合自己的BUY。新α批次必须保存足以重建业务事实的快照：

```text
batchNo
stocksId
alphaRuleVersion
signalTime
signalReferencePrice
entryTime
entryReferencePrice
r20
r1
R20
R1
alphaScore
rankPosition
stockUniverseVersion
featureDataAsOf
status
exitSignalTime
exitTime
exitReferencePrice
exitReason
netReturn
```

是否通过现有字段或必要审计扩展承载，由开发方案决定，但不得改变旧字段历史含义。

α批次从决策、待入场到实际成交后，必须持续保留α规则身份；公共入场、结算或批次组装不能把α规则版本、Alpha来源或分配规则覆盖为旧版默认值。决策事实与执行事实必须分开保存，不能用执行bar时间冒充目标变化的决策时间。

本策略长期采用“新增决策、复用交易基础设施”的最小实现边界：Alpha只新增日线收盘、横截面排名、phase、Top1/Top3目标决策和目标变化编排；轮次调度、槽位、资金、整数股数、跟随/偏离、批次状态、通知审计、BUY/SELL发送和幂等均复用现有能力。公共成交组装只能补充实际成交字段，不得无条件覆盖批次已经冻结的Alpha规则版本、来源和分配规则。当前首批整改及证据门禁以`vip_stock_alert_business_review_conclusion_one_time.md`为补充依据。

目标变化换仓的业务事实至少应能区分：

- 目标变化决策时间；
- 原仓退出执行bar及实际价格；
- 新仓入场执行bar及实际价格；
- 原仓、新仓各自的来源bar；
- `ALPHA_REBALANCE`关联的原BUY批次和新批次。

### 5.3 消息

Alpha消息必须使用已审核的、能够识别Alpha身份的新模板，与旧版BUY/SELL模板、旧版三类BUY依据和旧版五槽语义明确区分；但发送、审计、payload冻结、发送状态和幂等继续复用现有股票提醒基础设施，不新增第二套Alpha消息平台。Alpha初始入场和换仓消息均走Alpha感知的渲染分支；`ALPHA_REBALANCE`作为目标变化的策略退出原因和换仓关联事实使用，不要求回退为旧版消息模板。

Alpha必须使用能够识别Alpha业务身份的渲染分支，不能把`primaryStrategy=ALPHA`交给只认识旧版三类BUY的解析器，也不能复用旧版五槽文案解释Alpha。

BUY需要说明：

- α=0.04主策略；
- 20日反转是主要依据；
- 1日反弹占4%评分权重；
- Top1目标；
- 系统参考价、跟随窗口和系统不记录个人持仓；
- 不展示旧版qualityScore、旧版三类BUY依据或旧版五槽容量语义。

SELL需要说明：

- 原α BUY批次；
- 参考买卖价和扣费后净收益；
- `ALPHA_REBALANCE`；
- Alpha目标发生变化；
- 未跟随原BUY者无需操作。

换仓可以使用一条合并Alpha消息或两条同轮Alpha腿消息；无论采用哪种形式，SELL和BUY必须通过同一Alpha决策/换仓事实关联，至少可读回换仓决策ID、换仓关联ID、原仓批次、新仓批次和腿类型，不能将单侧消息发送成功当作完整换仓通知成功。Alpha模板可以与旧版BUY/SELL模板明确不同；`ALPHA_REBALANCE`不得称为止盈、止损或旧版风险SELL。

## 6. 旧版策略和切换边界

### 6.1 旧版的长期定位

旧版三类BUY和旧版五槽组合不再是当前新业务基线。其长期保留范围仅限：

- 切换前旧批次的历史收尾；
- 历史数据和历史收益的语义解释；
- 明确批准的紧急回退；
- 后续独立研究，不自动回到α主线。

旧版不能与α混合排序，也不能因为现有代码结构方便而重新成为α前置门槛。

### 6.2 存量批次

α主策略生效时：

- 关闭旧版新入场；
- 已有旧版批次保留原规则版本；
- 旧版批次按开仓时规则收尾；
- 旧版批次不能改写成α批次；
- 旧版SELL不能标记为`ALPHA_REBALANCE`；
- 旧版收益不与α收益混算。

这只是迁移期间的历史连续性，不代表旧版仍参与新业务。

旧版与α允许同时持有同一股票。相同股票不构成跨策略排他条件；但旧版和α必须保持独立组合CODE、批次来源、资金结算、规则版本、消息和收益统计，任何一方的SELL都只能配对自己的BUY。
### 6.3 回退

如α主链出现无法接受的P0/P1问题，是否恢复旧版新入场必须由业务负责人单独批准。关闭α不能自动把旧版新入场重新打开，也不能把已建立的α批次转交旧版规则。

## 7. 数据、失败和审计原则

### 7.1 数据不足

数据不足时：

- 不产生新α BUY；
- 不产生伪造α SELL；
- 不用补值完成排名；
- 记录缺失股票、自然日、窗口和数据版本；
- 当前持仓不因缺数被强制解释为目标变化。

Torn股票按7×24小时交易处理，不采用周末或节假日休市假设。周六、周日只要35支股票均形成合法日线收盘，就应正常计入共同有效日；缺任一成员时仍按完整共同有效日规则整体排除，不得为了填满日期而补值或跳过真实完整日期。

### 7.2 执行失败

下一根bar缺失、断层、陈旧或价格不满足执行条件时：

- 不跨断层寻找更晚bar冒充原成交；
- 不产生孤儿SELL；
- 不产生没有合法成交来源的新批次；
- 记录明确失败原因；
- 等下一次正式决策点重新评估，不追补过期目标。

### 7.3 业务审计

每次α决策必须能回答：

```text
当时使用了哪一天的收盘价？
股票池是什么？
r20、r1、R20、R1和alphaScore是多少？
为什么选择或保持Top1？
为什么产生或没有产生BUY？
如果换目标，原BUY批次是什么？
退出成交是否是下一根严格连续bar？
```

推荐展示可以根据产品形态调整，但不能重新选择α权重，也不能把排名结果无规则地伪装成旧版BUY/SELL/HOLD。第二批需单独形成验收口径。

## 9. 研究证据和长期复审

当前α=0.04的历史结果属于：

```text
RETROSPECTIVE_EXPLORATORY_OOS_ALREADY_CONSUMED
```

当前α=0.04是已经研究过的候选中，业务上选择的最高收益主线；它不是旧版候选之一，也不是旧版策略的辅助排序。它不等于已经证明未来所有市场环境下绝对最优，也不构成收益承诺。

规则冻结后：

- 新数据用于前向观察，不用于事后改写本次规则；
- 新版本必须先形成明确规则差异，再做独立回放；
- 没有新证据不得自动调节α权重；
- 研究结果与生产消息验收分开记录；
- 日线研究结果不得当作严格15分钟或分钟版结果；
- 生产部署前没有Alpha预填数据不构成失败；预填必须在生产部署后通过超管机器人指令执行，并在正式新入场前完成质量校验；
- 真实Alpha BUY和真实配对`ALPHA_REBALANCE` SELL是功能验收证据，不得用离线回放、单元测试或预填结果替代。
- Alpha整改必须优先通过复用既有BUY/SELL消息发送和审计链完成，不新增独立Alpha消息产品；具体整改门禁见`vip_stock_alert_business_review_conclusion_one_time.md`。
- 本批次通知采用单次自动发送语义：`PENDING → SENT`或`PENDING → FAILED`，`FAILED`不由普通调度自动重试；通知失败不回滚已提交交易，换仓合并消息失败时不得把单腿标记为完整送达。

未来如要增加止盈、硬风险、时间退出、动态SELL、TopN、风格门禁或新资金结构，必须作为另一个业务决策单独冻结，不能通过本次实现顺手加入。

## 10. 与一次性验收文档的关系

一次性验收文档负责冻结本次第一批股票提醒的完整验收细节，包括：

- α公式和输入；
- Top1、每5日和Top3迟滞；
- 单一逻辑持仓和100%目标资金；
- 下一连续15分钟bar成交；
- 唯一正常SELL `ALPHA_REBALANCE`；
- 旧版存量批次收尾；
- BUY/SELL消息和业务确认；
- 第二批炒股推荐边界。

本文只保留这些规则的长期业务结论。后续文档不得把α降为次要策略、次级排序或旧版竞争分支；出现此类内容均视为过期内容，应以本次验收文档和最新业务确认修正。

## 11. 长期禁止事项

- 不把α作为旧版候选之一；
- 不让旧版BUY与α共同争夺新入场；
- 不让旧版qualityScore覆盖α综合评分；
- 不把Top1扩展成Top3或Top5；
- 不把4%解释成资金比例；
- 不把日线α解释成15分钟或分钟α；
- 不用旧版固定SELL规则重新定义αSELL；
- 不因数据缺失补值、跨断层成交或伪造收益；
- 不用历史消费数据继续反向调参；
